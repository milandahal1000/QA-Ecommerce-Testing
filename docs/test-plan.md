# Test Plan – SauceDemo E-Commerce Application

## 1. Project Information

- **Project Name:** SauceDemo E-Commerce QA Testing
- **Application:** [https://www.saucedemo.com/](https://www.saucedemo.com/)
- **Project Type:** Web Application Testing
- **Testing Approach:** Manual and Automation Testing
- **QA Engineer:** Portfolio Project
- **Status:** Test Planning

## 2. Objective

The objective of this project is to evaluate the functionality, usability, reliability, and behavior of the SauceDemo e-commerce application through manual and automated testing.

The project aims to identify defects, validate application workflows, and demonstrate practical Quality Assurance skills.

## 3. Testing Scope

### In Scope

1. User authentication and logout
2. Product inventory and display
3. Product sorting
4. Shopping cart operations
5. Checkout form validation
6. Order overview
7. Order completion
8. Navigation and session behavior

### Out of Scope

1. Real payment gateway processing
2. Actual financial transactions
3. Production database security assessment
4. Load and stress testing
5. Infrastructure penetration testing

## 4. Testing Methodology

The project will use the following testing methodologies:

- Functional Testing
- Positive Testing
- Negative Testing
- Boundary Value Testing
- UI Testing
- Regression Testing
- Cross-Browser Testing

## 5. Testing Tools

| Tool        | Purpose                                             |
| ----------- | --------------------------------------------------- |
| Python      | Automation programming                              |
| Selenium    | Browser automation                                  |
| Pytest      | Test execution                                      |
| Postman     | API testing, where suitable endpoints are available |
| Git         | Version control                                     |
| GitHub      | Project documentation and hosting                   |
| Pytest HTML | Test reporting                                      |

## 6. Test Environment

- Operating System: CachyOS Linux
- Browser: Google Chrome / Chromium / Brave
- Programming Language: Python
- Automation Framework: Selenium + Pytest
- Application Environment: Public SauceDemo demo website

Record exact browser, Python, Selenium and Pytest versions during setup.

## 7. Entry Criteria

Testing can begin when:

- Application is accessible.
- Test environment is configured.
- Demo credentials are available.
- Test scenarios are documented.

## 8. Exit Criteria

Testing can be considered complete when:

- All planned test cases have been executed.
- Critical and high-priority defects are documented.
- Automated tests have been executed.
- Test results are recorded.
- Final test execution report is prepared.

## 9. Defect Management

Each identified defect must contain:

- Bug ID
- Bug title
- Description
- Steps to reproduce
- Expected result
- Actual result
- Severity
- Priority
- Evidence or screenshot
- Status

## 10. Deliverables

- Test Plan
- Test Scenarios
- Manual Test Cases
- Bug Reports
- Automation Test Scripts
- Test Execution Reports
- GitHub README

## 11. Project Completion Goal

The final objective is to create a documented and reproducible QA testing portfolio demonstrating practical manual testing, Selenium automation, Python programming, and professional defect reporting.
